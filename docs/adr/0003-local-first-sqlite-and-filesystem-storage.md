# ADR-0003: ローカルファースト設計：SQLite メタデータ管理とファイルシステム分離

- **ステータス**: Accepted
- **日付**: 2026-11-25
- **関連フェーズ**: Phase 1

## コンテキスト（背景・課題）

大学数学・大学物理の学習では、大容量の問題 PDF、高解像度画像、生成解答 PDF、グラフ（SVG/PNG）、構造化解答 JSON、会話履歴、計算検証履歴を長期間にわたりオフラインでも安全に管理する必要がある。

## 決定内容

- **責務分離**: メタデータ・構造化データ・会話履歴・ジョブキューは **SQLite（`sqlx` 管理、WAL モード、外部キー有効）** に保存し、PDF・画像・グラフ等のバイナリ実体は **ローカルファイルシステム（`FormulaDesk/attachments/` 等）** に保存する。
- **相対パス管理**: DB には OS 依存の絶対パスを保存せず、Tauri パス API で解決されるアプリ管理領域からの相対パスを保存する。
- **整合性保護**: すべての原本・生成ファイルに UUID と SHA-256 を付与し、原本不変・重複検出・一時ファイル経由のアトミックリネーム保存を徹底する。
- **機密分離**: OAuth トークンや API キーは SQLite に平文保存せず、OS キーチェーン（`keyring` 等）に保管する。
- **非同期方針**: SQLite ファイル自体のクラウド自動同期や端末間同期は実装しない。

## 検討した代替案

1. **PDF・画像を SQLite BLOB として格納**: DB ファイルが肥大化し、バックアップ・PDF.js ストリーミング・外部アプリ連携・Typst 埋め込みの効率が悪い。
2. **すべてをフラットな JSON/Markdown ファイルのみで管理**: バージョン管理・全文検索・トランザクション整合性・Drive 永続ジョブキューの実装が複雑化し破損リスクが高まる。

## 結果・トレードオフ・リスク

- **利点**: 高速な検索・トランザクション整合性・オフライン可用性・シンプルなバックアップ構成を両立できる。
- **トレードオフ**: DB レコードと実ファイル間の孤児ファイル整合性を保つ設計（ロールバック削除・定期 GC）が必要。
