# ADR-0004: Typst による PDF 生成と LaTeX→Typst 変換層（Phase 0 検証確定）

- **ステータス**: Accepted（Phase 0 PoC の実測結果に基づき確定）
- **日付**: 2026-11-25
- **関連フェーズ**: Phase 0 / Phase 2 / Phase 6

## コンテキスト（背景・課題）

大学数学・大学物理の解答を美しい日本語・数式・図グラフ付き PDF として生成したいが、従来の LaTeX（TeX Live / LuaLaTeX）は数 GB の外部環境インストールをユーザーに強いるため、ローカルファーストな OSS デスクトップアプリの体験を大きく損なう。一方で、AI 出力およびチャット表示（KaTeX）では LaTeX 数式が事実上標準である。

## Phase 0 技術検証の実測結果（`poc/pdf-typst-poc` / `poc/pdfjs-poc`）

1. **Embedded Typst クレート（`typst 0.15.1` + `typst-pdf 0.15.1` + `typst-assets 0.15.1`）**:
   - カスタム `SandboxedWorld` により、A4 3 ページ（日本語 `Noto Serif JP` + 大学数学・物理 12 数式 + Cauchy-Schwarz 証明 + SVG ベクター図 + PNG ラスター図）を **コンパイル 214 ms + PDF 出力 207 ms（計 421 ms / 129 KB）** で生成。
   - `World::file` / `World::source` で `VirtualRoot::Package(_)`（外部パッケージ取得）および未登録パス参照（`#read("Cargo.toml")`）を完全に遮断できることを確認。
   - 外部サイドカーバイナリ管理・OS 別バンドルが不要。
2. **LaTeX → Typst 変換ライブラリ比較（大学数学・物理 12 数式 + 未対応マクロ 1 件）**:
   - `mitex 0.2.4`（生出力）: `6/12` 合格（`mitexsqrt` / `mitexmathbf` / `pmatrix` 等のヘルパー定義および Typst 0.15 シンボル差が原因）。
   - `tex2typst-rs 0.4.1`（生出力）: `9/12` 合格（Typst 0.15 シンボル差に加え、`pmatrix`/`cases` の区切り括弧を `delim: #none` とする課題、および未対応マクロのバックスラッシュ除去を確認）。
   - **`mitex 0.2.4` + Typst 0.15 シンボル正規化（`diff→partial`, `planck.reduce→planck`, `angle.l/r→chevron.l/r`）+ 純粋オフライン Typst 互換プレリュード**: **`12/12`（100%）コンパイル合格**。`pmatrix` 括弧・`cases` 波括弧を正確に保持し、未対応マクロ（`\totallyUnknownCustomMacro`）をパース段階で即座にエラー検出できることを確認。
3. **PDF.js (`pdfjs-dist 5.7.284`) 互換性**:
   - 生成された 3 ページ A4 PDF（`595.3 x 841.9 pt`）を問題なく読み込み、日本語および数式テキスト（`𝑖 ℏ 𝜕 𝜕 𝑡 | 𝜓 ( 𝑡 ) ⟩ = 𝐻 ̂ | 𝜓 ( 𝑡 ) ⟩` 等）が抽出可能であることを確認。

## 決定内容

1. **組版エンジン実行方式**: **Rust クレート組み込み（`typst` + `typst-pdf` + `typst-assets`）を採用する**。
   - Phase 2 レビュー修正で、アプリ自身の実行ファイルを専用ワーカーモードで起動する。構造化解答、設定、登録済みアーティファクトを実行ごとの一時ディレクトリで渡し、LaTeX 変換から PDF 出力までを子プロセス内で実行する。厳格なインメモリの `SandboxedWorld` で外部パッケージと未登録のファイル参照を拒否する。
   - 親は 20 秒の期限で子プロセスを強制終了し、終了を待ってからエラーを返す。Windows では Job Object も使用する。組版結果と LaTeX エラーは構造化したまま親へ返す。
2. **LaTeX → Typst 変換方式**: **`mitex` クレート + FormulaDesk Typst 0.15 シンボル正規化 + オフライン互換プレリュード** を第一変換器とし、変換結果を必ず Typst コンパイラ検証パスに通す。
   - パースエラーまたは Typst コンパイルエラーが発生した数式は、黙って削除・誤置換せず構造化エラー（対象ステップ・元 LaTeX・理由）を返却し、ユーザー編集または標準 LaTeX への制限付き再生成へ誘導する。
3. **セキュリティ**: AI 生成の任意 Typst コードは実行せず、構造化解答 JSON のテキスト要素はすべて `escape_typst_text` でエスケープした上で検証済みテンプレートへ埋め込む。
4. **日本語フォント**: SIL OFL 1.1 で再配布可能な `Noto Serif JP` / `Noto Sans JP`（または `BIZ UD` 系）を標準候補とし、Phase 6 で同梱方式とライセンス表記を確定する。

## 検討した代替案

1. **Typst CLI サイドカー実行**: プロセス隔離の利点はあるが、Windows/macOS/Linux のサイドカー配布・更新・パス解決コストが増える。Embedded Typst でも `SandboxedWorld` によるハードなファイル/ネットワーク遮断と高速コンパイル（~420 ms）が実証されたため、まずは Rust 組み込みを採用する。Phase 2 レビュー修正でも同じ実行ファイルを配布し、ワーカー起動時のフォント初期化コストを受け入れる。
2. **`tex2typst-rs` 単独採用**: `pmatrix` / `cases` の区切り文字欠落や未対応マクロ検出の弱さがあるため不採用（補助ベンチマーク対象として知見を保持）。
3. **HTML + KaTeX → Chromium 印刷 / TeX Live**: 学術組版品質・環境導入障壁の観点で不採用。

## 結果・トレードオフ・リスク

- **利点**: 単一バイナリ配布、TeX Live 不要、サブ秒コンパイル、完全オフライン、`World` 境界での物理的サンドボックス、大学数学・物理数式の高精度変換と未対応マクロの厳格検出を両立。
- **トレードオフ**: `typst` クレート群の初回 Rust ビルド時間が長め（~1〜2 分）であり、`typst` メジャーアップデート時にシンボル正規化テーブルの追従メンテナンスが必要。
