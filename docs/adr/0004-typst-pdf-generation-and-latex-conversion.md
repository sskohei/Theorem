# ADR-0004: Typst による PDF 生成と LaTeX→Typst 変換層（実行方式は Phase 0 で確定）

- **ステータス**: Proposed（Phase 0 PoC の比較検証結果により実行方式・変換ライブラリを確定予定）
- **日付**: 2026-11-25
- **関連フェーズ**: Phase 0 / Phase 2 / Phase 6

## コンテキスト（背景・課題）

大学数学・大学物理の解答を美しい日本語・数式・図グラフ付き PDF として生成したいが、従来の LaTeX（TeX Live / LuaLaTeX）は数 GB の外部環境インストールをユーザーに強いるため、ローカルファーストな OSS デスクトップアプリの体験を大きく損なう。一方で、AI 出力およびチャット表示（KaTeX）では LaTeX 数式が事実上標準である。

## 決定内容（暫定方針・検証対象）

1. **組版エンジンとして Typst を採用する**。
2. **内部共通数式形式は LaTeX とし、専用の LaTeX→Typst 変換層を設ける**。LaTeX 文字列の直接埋め込みや未対応記法の黙殺・誤置換を禁止する。
3. **構造化解答 JSON のみを検証済みテンプレートへ埋め込む**（AI 生成の任意 Typst コード実行を禁止）。
4. **Phase 0 で以下を比較検証し確定する**：
   - **Typst 実行方式**: Rust `typst` crate 組み込み vs Typst CLI サイドカー実行（配布性・クラッシュ隔離・タイムアウト・バイナリサイズ・API 安定性を評価）
   - **LaTeX→Typst 変換**: `mitex` / `tex2typst` / 制限付き AST 変換の精度とエラー報告性能
   - **日本語フォント**: 再配布可能ライセンス（OFL 等）を持つフォントの選定

## 検討した代替案

1. **HTML + KaTeX → Chromium 印刷（PDF 化）**: ページ跨ぎ・学術組版品質・数式改行・見出し孤立制御で Typst に劣り、WebView 依存の不安定さがある。
2. **TeX Live / Tectonic 利用**: TeX Live は導入障壁が極めて高く、Tectonic は日本語（CJJ/upLaTeX/LuaLaTeX）対応とオフラインバンドルに課題がある。

## 結果・トレードオフ・リスク

- **利点**: ミリ秒〜秒単位の高速コンパイル、TeX Live 不要、高品質な数式・日本語組版と SVG 埋め込み。
- **リスク**: 大学数学・物理の特殊な LaTeX マクロで変換失敗が発生し得る。変換失敗を明確なエラーとして検出し、ユーザー手動修正または標準 LaTeX への制限付き再生成 UI で救済する。
