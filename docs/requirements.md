# FormulaDesk 要件定義書（Requirements）

> **ステータス**: Draft v1.0
> **最終更新**: 2026-11-25

---

## 1. 優先度およびフェーズ区分

- **P0（MVP 必須）**: Phase 0〜Phase 4 で実装し、MVP 完成条件を満たすために必須の要件
- **P1（高度な学習機能）**: Phase 5 で実装する拡張学習機能
- **P2（正式公開・展開）**: Phase 6 で実装するクロスプラットフォーム・配布・多言語対応

---

## 3. 非機能要件（Non-Functional Requirements）

### 3.1 可用性・オフライン耐性（NFR-AVAIL）

- **NFR-AVAIL-01**: 外部ネットワーク切断時や AI/Drive 障害時でも、保存済みの問題・解答・PDF・会話履歴・計算結果を閲覧・整理できること。
- **NFR-AVAIL-02**: AI ハーネスプロセスや Science MCP プロセスが異常終了してもアプリ本体はクラッシュせず、状態を復旧・通知できること。
- **NFR-AVAIL-03**: ストリーミング途中で中断したメッセージは中断状態を保持し、アプリ再起動時に不整合を起こさないこと。

### 3.2 データ整合性・永続性（NFR-DATA）

- **NFR-DATA-01**: SQLite の外部キー制約を有効化し、複数テーブル更新はトランザクションで保護すること。
- **NFR-DATA-02**: ファイル保存は一時ファイル書き込み後のアトミックリネームで行い、異常終了時の破損を防止すること。
- **NFR-DATA-03**: DB 内には絶対パスを保存せず、アプリ管理領域からの相対パスで管理すること。
- **NFR-DATA-04**: 不要な一時ファイルや終了済みワークスペースのクリーンアップ手段を提供すること。

### 3.3 パフォーマンス・応答性（NFR-PERF）

- **NFR-PERF-01**: AI 実行・PDF 生成・Drive アップロード・計算ツール実行は非同期（Tokio）で行い、UI スレッドをブロックしないこと。
- **NFR-PERF-02**: AI 応答はストリーミングで逐次表示し、ユーザーのキャンセル操作に速やかに応答すること。
- **NFR-PERF-03**: Science MCP 計算および Typst PDF 生成には実行タイムアウトと入力サイズ上限を設けること。

### 3.4 セキュリティ・プライバシー（NFR-SEC）

- **NFR-SEC-01**: API キー・OAuth トークン・パスワードを SQLite に平文保存せず、OS キーチェーン等の安全なストレージへ保存すること。
- **NFR-SEC-02**: エージェントによる任意シェル実行はデフォルト禁止とし、DB・Drive 認証情報・無関係ファイルへのアクセスを遮断すること。
- **NFR-SEC-03**: 問題 PDF・画像・参考資料・AI 出力を信頼できない入力（プロンプトインジェクション源）として扱うこと。
- **NFR-SEC-04**: Science MCP で任意 Python コード実行および `eval`/`exec` を禁止すること。
- **NFR-SEC-05**: AI 生成の任意 Typst コードを無制限実行せず、構造化データのみ検証済みテンプレートへ埋め込むこと。
- **NFR-SEC-06**: パストラバーサルおよびシンボリックリンク経由の領域脱出を防止すること。
- **NFR-SEC-07**: Tauri Capability と CSP を最小権限に設定すること。
- **NFR-SEC-08**: クラウド AI 利用時に外部へデータが送信されることをユーザーへ明示すること。
- **NFR-SEC-09**: ログに API キー、OAuth トークン、パスワード、問題文全文、会話履歴全文を出力しないこと。

### 3.5 コンプライアンス・利用規約遵守（NFR-COMP）

- **NFR-COMP-01**: 公式 AI ハーネスを改変せず、非公開 API・認証トークン非公式抽出・他クライアント偽装を行わないこと。
- **NFR-COMP-02**: ユーザーの許可なく従量課金 API キーへ自動フォールバックしないこと。
- **NFR-COMP-03**: 利用条件が確認できないサブスクリプション認証方式や無人バッチ処理・利用上限回避機能を有効化しないこと。
- **NFR-COMP-04**: 依存ライブラリおよび同梱フォントのライセンス（MIT 互換性・再配布条件）を確認すること。

### 3.6 保守性・品質・移植性（NFR-MAINT）

- **NFR-MAINT-01**: TypeScript strict モード（不要な `any` 禁止）、Rust `Result` 徹底（本番 `unwrap`/`expect` 禁止・`clippy`/`fmt`）、Python 型ヒント＋`Ruff`＋`pytest` を遵守すること。
- **NFR-MAINT-02**: UI・Application Services・Adapters・Persistence の責務分離を維持し、大規模単一ファイルを避けること。
- **NFR-MAINT-03**: Mock Adapter により外部認証情報なしで CI 自動テストが完結し、かつモック結果と実外部接続検証を明確に区別すること。
- **NFR-MAINT-04**: Windows 11 を最優先としつつ、OS 依存コードを分離し macOS/Linux への移植性を保つこと。

## 4. 明確な禁止事項

1. 仕様書だけを作成して実装完了とみなすこと
2. UI のみを実装してバックエンド機能が動作するように見せかけること
3. テストを実行せず成功と報告すること
4. 存在しない API や未確認の仕様を推測で実装すること
5. 認証情報・OAuth クライアントシークレットをリポジトリへコミットすること
6. ユーザーの許可なく外部サービスで従量課金を発生させること
7. サブスクリプションの利用制限を回避する仕組みを実装すること
8. 不要な権限を AI エージェントに付与すること
9. 本仕様に存在しない専用バックエンドサーバーやクラウド DB を無断導入すること
10. 未実装・未検証のプロバイダーや機能を動作確認済みとして表示すること
